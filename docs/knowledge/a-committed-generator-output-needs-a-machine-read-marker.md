# A committed generator output needs a machine-read marker

Almost every generated file in this repository is gitignored —
[ADR-0014](../adr/0014-generated-files-are-not-committed.md) is the decision
and the measurements behind it. A handful are committed anyway, because they
are inputs a person accepted or because a build step needs them present.

`apps/borsouvertures/site/src/config/openingsCacheVersion.ts` is one: it is
written by `apps/borsouvertures/scripts/build-openings.ts` and consumed by
`vite.config.ts`.

It used to carry a `generated, do not edit` header. `borso/no-comments`
removed it in PR #81, and for a while the file had **no way of saying it was
generated**. Editing it by hand looked entirely reasonable, and the next build
would have silently discarded the edit.

## The marker

`@generated` is the convention, not a local invention. GitHub's linguist and
several review tools recognise it and collapse the file in a diff, so it is
machine-read in the sense the standard requires: it has a reader that behaves
differently without it.

    // @generated by apps/borsouvertures/scripts/build-openings.ts

`borso/no-comments` allowlists `@generated` as a tag, and the generator emits
the line, so the marker cannot drift from the file it marks.

## When to reach for it

Only for an output that is **committed**. A gitignored generated file needs
nothing — it is not in the tree a reader browses. If you find yourself adding
`@generated` to a file, ask first whether ADR-0014 says it should be committed
at all; the marker is for the exceptions, and the exceptions are listed in
`.gitignore` by their absence.

Name the generator in the line. *"This is generated"* leaves the reader
hunting for what to run; *"generated by `<path>`"* is the whole answer.
