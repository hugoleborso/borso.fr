## Notes

- **01 FAIL.** The browser sends the reorder with `X-Pragma-Client`. API Gateway's CORS preflight does not allow that header, so the browser blocks the `PUT`, the optimistic order rolls back with no visible error, and lea's tab receives nothing. The same flow passes on local `pnpm dev` (row 20), whose CORS echoes any requested header. The server broadcast also works when the write bypasses CORS (rows 02, 03). The defect is the deployed CORS allow-list, not the invalidation logic.
- **09 FAIL.** This breaks every browser write on the preview, and sign-in too. The login form shows "Unexpected error." because `POST /api/auth/login` carries the header and its preflight fails. Measured with `curl -X OPTIONS … -H 'Access-Control-Request-Headers: content-type,x-pragma-client'`. It answers 204 with only `vary` and `apigw-requestid`. Requesting `content-type` alone answers `access-control-allow-headers: authorization,baggage,content-type,sentry-trace,x-ballot-token`. That list matches `CORS_ALLOWED_REQUEST_HEADERS` in `infra/cdk/src/constructs/lambda-api.ts`, which does not include `x-pragma-client`. This was reproduced in a session without the spy script, where the login `POST` never completed after `OPTIONS 204`. The same CORS config is the one prod would use (inferred from the shared construct), so a merge would break sign-in and every write in prod.
- **14 UNVERIFIABLE.** No write in this run produced `written:["all"]`, so the `all` branch could not be triggered from outside.
- **16 UNVERIFIABLE.** A 410 needs a connection that API Gateway still lists but that is gone. No browser action produces one on demand, and `scripts/db-read.sh` reads production, not the preview schema.
- **17 UNVERIFIABLE.** No send failure or slow send could be induced. Sentry was not read.
- **19 UNVERIFIABLE.** The status a `$default` integration returns is not visible to a WebSocket client. Its observable effect (no broadcast, no disconnect) passed as row 18. Row deletion on `$disconnect` needs the preview table, as in row 16. On the client side the hidden tab's socket did close (row 04).
- **21 UNVERIFIABLE.** `apps/pragma/api/src/main.dev.ts` sets `WEBSOCKET_CLIENT_URL` to `ws://localhost:3004` every time, so neither `pnpm dev` nor the preview has a configuration without a socket URL. Row 22 covers the client half by simulating the answer.
- Row 15 stripped `X-Pragma-Client` from lea's own delayed write so that it could pass CORS. As a result her tab also received the message for her own write (at 184652). That is an effect of the test, not a finding.
- Preview data changed by this run: setlist `2756b530…` order, hugo's phone (`+33600000001`), hugo's guitar mastery on Lightning (7) and lea's Chant mastery on Lightning (8). An OAuth client `vv-validator` was registered and granted for hugo.
- The pixel-content check returned `[]` after every screenshot.

## Verdict: FAIL
