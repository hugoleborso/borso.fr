## Notes

- _(A11 / Note 1)_ `SetlistEditor.tsx:288` passes `songDefaultLineup={song?.defaultLineup ?? {}}` to `SetlistEntryRow`. The `?? {}` fallback handles the transient case where an entry's `songId` doesn't resolve in `songsQuery` (in-flight query, optimistic insert, true data inconsistency). When it triggers, the LineupEditor receives `defaultLineup={}`, so the Reset button still renders and a Reset+Save will persist `null` (collapsed from the empty form). That's semantically harmless — `null` override means "fall back to whatever the song default ends up being once it loads". Not a blocker, and the entry's title already handles the same missing-song case at `SetlistEditor.tsx:277` (`title={song?.title ?? entry.songId.slice(0, 8)}`).
- _(Note 2 — post-Reset edits)_ The spec's use case 3 names a strict three-step flow: Reset → review → Save. The implementation's `wasResetRef` is set on Reset and never cleared by subsequent field edits, so a user who clicks Reset, edits a field, then clicks Save will persist `null` (the wasReset branch) — silently discarding the post-Reset edit. The spec does not name this edge case, the plan's Use-case-3 row does not constrain it, and the canonical happy path (Reset → Save) works correctly. Flagging as a future-cleanup smell, not a blocker: the cleanest fix would be to clear `wasResetRef.current = false` inside a `form.Field`'s `handleChange` (or via a `form.subscribe` to dirty state). Not requested by the spec or plan, so leaving it.
- _(Note 3 — `wasReset` semantics across reopens)_ Verified explicitly per the brief's angle 1: `wasResetRef` lives inside `LineupEditorContent` (line 97), and `LineupEditor` returns `null` when `open=false` (line 82). The close → reopen transition unmounts `LineupEditorContent`, which causes `useRef` to re-initialise to `false` on the next mount. No leak path exists.
- _(C01 / Note 4)_ `LineupEditor.tsx` runs at 96.42% branches because line 112 (`if (defaultLineup === undefined) return;` inside `handleResetToDefault`) is unreachable from the rendered Reset button (the button is rendered iff `defaultLineup !== undefined`, so by the time `handleResetToDefault` fires the early-return is dead). The line is a defensive guard for the type-narrowing tooling. `LineupEditor.tsx` is NOT subject to the `*.core.ts`/`*.utils.ts` 100% gate (it's a JSX molecule, not a pure helper), so this is informational only.
- _(Round-1 PASS regression sweep)_ `git diff 263b0b1...HEAD -- apps/pragma/api/` is empty → cascade transaction, controller-as-dispatcher, type-assertion ban, and the back-e2e cascade test all unchanged.
