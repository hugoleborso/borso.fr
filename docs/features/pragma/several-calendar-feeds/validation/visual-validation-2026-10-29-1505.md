## Notes

- **11 FAIL.** With at least one calendar connected, a refused address closes the add field and throws away what the member typed. Only "Add a calendar" and the red message stay (`05-invalid-address.png`, reproduced with `ftp://nope` and Enter). The same refusal at zero calendars keeps the field open with the value in it (`16-…png`). So the field behind "Add a calendar" does not behave like the field "as before". To fix a typo the member has to reopen the field and paste the secret address again.
- **21 FAIL.** When a failing feed declared no name, Find a slot prints the bare "Hugo's calendar needs reconnecting". With five such feeds it printed that line five times. Account › Calendar labels the same feeds "Calendar N" (`04-…png`), but Find a slot does not reuse that label. The member cannot tell which calendar to reconnect or remove. This is the exact case the spec's Goal ("tell them apart and remove the right one") and Screens ("names the failing calendar") address. The French view has the same gap ("L'agenda de Hugo est à reconnecter" next to "Agenda 2" on Account).
- **22 FAIL.** At 375 px the name column is about 134 px and truncates with an ellipsis. It has no `title` and no wrap. "Holidays in United Kingdom" and "Holidays in United States" both render as "Holidays in Unite…" (`09-…png`). The removal dialog shows the full name (`10-…png`), so a wrong removal can still be caught there. The list itself does not let the member tell the calendars apart. Google primary calendars are named after the account email, so long shared prefixes are the common case (inferred).
- **27 UNVERIFIABLE.** The trim and 120-character cap need a feed whose `X-WR-CALNAME` is padded or longer than 120 characters. No such public feed was available. The local fixture route (`/api/__test/calendar-feeds/*`) is on `http://localhost`, which both the save and the read path refuse.
- **Setup disclosure (rows 08, 20, 21).** One `UPDATE calendar_feed SET name = …` was run against the local dev database (`pragma_dev_*`). It set "Stale name" (row 08), "Work" (row 20) and "Gigs" (row 20). No repository file was changed. `pnpm dev` reseeds on its next start.
- Every screenshot passed the broken-image scan (`[]` each time).

## Verdict: FAIL
