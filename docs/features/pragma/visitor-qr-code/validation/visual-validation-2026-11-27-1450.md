## Notes

- Row 10 (UNVERIFIABLE). Only `http://localhost:5174/` was in scope. Row 09 shows the value is `location.origin + "/"` rather than a hard-coded host, which is what makes the production and preview values follow (inferred). Scanning the code on a preview with a phone camera needs a preview URL and a device.
- Row 12 (FAIL). At 375 px the code is capped at 320 px, though the sheet allows 343 px. The cap meant for a computer also applies on a phone, so the code is 23 px narrower than the spec's "as wide as the sheet allows at 375 px". The white square is centred with 27.5 px on each side, while the title row above uses the full 16 px padding.
- Row 14, observation. Opening the sheet the first time requested the JetBrains Mono font file for the address line. The code itself made no request and rendered offline. Whether the installed app serves that font from its cache was not checked.
- Setup left behind. To check row 04, this run created one practice session in the local dev database, shown on home as "Sat, Nov 28, 2026 · 21:00", since the seed holds none. Home now shows that practice as the next session. The next `pnpm dev` reseed removes it.
- The QR content was checked by re-encoding rather than by a camera scan. No decoder was available in the sandbox (no `BarcodeDetector`, `zbarimg` or OpenCV), and this is logged as friction.

## Verdict: FAIL
