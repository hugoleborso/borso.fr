- Tooling: agent-browser through `scripts/browser.sh`'s settings, Chromium 1243 headless, launched with `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream` as the spec's test strategy asks

## Harness

- The local API has no bucket and no SSM parameters. `AWS_ENDPOINT_URL_S3` and `AWS_ENDPOINT_URL_SSM` pointed at a small local HTTP server on port 9000 that stores `PUT` bodies, serves them back with range support and CORS, answers `GetParameter` with a generated VAPID key pair, and, new in this run, answers `DeleteObjects` by removing the named keys. `UPLOADS_BUCKET=pragma-local`, dummy AWS keys.
- Presigned URLs use the host `pragma-local.localhost`. Chromium resolves it, Node does not, which is why the previous run saw every audio delete fail. An `/etc/hosts` line for that host was added for the run and removed afterwards.
- Seed data: one practice session created through `POST /api/sessions` two hours before the run, with the seeded "Set principal" setlist attached.
- Notifications permission granted with CDP `Browser.grantPermissions`. Push was delivered for real: the browser subscribed to FCM through the sandbox proxy, and the API's `web-push` sends reached it. A CDP probe attached to the service worker recorded every `push` event it received.
- Touch rows were driven with CDP `Input.dispatchTouchEvent` after `Emulation.setTouchEmulationEnabled`, because `scripts/argent.sh` still fails to start (see row 44).
- This run was executed by the workflow subagent directly. The subagent has no `Agent` tool to dispatch the dedicated `visual-validator`, so the standalone-agent rule could not be applied as written.

## Notes

- **06.** Closed by `b918fbb3`. Rows now wrap. When the session is "no session", the break can fall between "no" and "session"; every fact stays visible.
- **15, 30 to 33, 40.** The spec's test strategy expected the push service to be out of reach. Here it was reachable: headless Chromium subscribed to FCM through the sandbox proxy, and the sends arrived. These rows are therefore observed, not inferred from the faked adapter.
- **20, 44.** The timeline mark is 12 × 24 px. An exact touch lands, but on a phone it is a small target. The thread chip (37 × 44 px) gives the same seek. The spec sets no size, so this is not a FAIL.
- **25.** Needs iOS Safari.
- **28.** The previous run marked this UNVERIFIABLE because of the harness: Node could not resolve `pragma-local.localhost`, and the stand-in did not delete. Both were fixed in the harness, not in the code.
- **34.** No system notification can be clicked in headless Chromium. The URLs in the payloads point at the right pages.
- **44.** `scripts/argent.sh` looks for `chrome-linux/chrome` and the image ships `chrome-linux64/chrome`, so it fails before starting. CDP `Input.dispatchTouchEvent` sent real touch events instead, but `(pointer: coarse)` was not emulated.
- Console: one React warning about `memberRows-testid` on the Members page, outside this feature. No broken `<img>` in any screenshot. While offline, a song page never opened before does not load ("This page could not be loaded"). That is the existing offline cache, which the spec does not change.
