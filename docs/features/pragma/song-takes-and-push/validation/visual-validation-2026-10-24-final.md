# Visual validation — Members record or upload takes of a song, replay its versions newest first, comment on them, and get a push notification when the band changes something

- Spec: [`../spec/spec.md`](../spec/spec.md)
- Dev URL: http://localhost:5174/ (`pnpm dev` in `apps/pragma`, local Postgres through its `dev:db`), plus a production build served by `vite preview` on http://localhost:4173/ for the push rows, because the service worker registers only outside dev
- Run at: 2026-10-24T14:45Z to 15:24Z
- Tooling: agent-browser 0.35.2 through `scripts/browser.sh`, Chromium 1243 headless. The fake-microphone flags `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream` were passed with `--args`, because `scripts/browser.sh` overwrites `AGENT_BROWSER_ARGS`. User agents were set with `AGENT_BROWSER_USER_AGENT`, one browser session per user agent, with a sign-in each time.
- Branch: `claude/pragma-takes-and-push` at `66425fcd`
- Previous runs: [`visual-validation-2026-10-24-0102.md`](./visual-validation-2026-10-24-0102.md) (takes and push), [`visual-validation-2026-10-24-install-banner.md`](./visual-validation-2026-10-24-install-banner.md) (install banner)

## Harness

- The local API has no bucket. `AWS_ENDPOINT_URL_S3` pointed at a small HTTP stand-in on port 9000. It stores `PUT` bodies, serves them back with range support and CORS, and handles `DeleteObjects`. `UPLOADS_BUCKET=pragma-local` and dummy AWS keys were set. For the run only, `/etc/hosts` mapped `pragma-local.localhost` to 127.0.0.1 so Node could reach the presigned host. The line was removed afterwards.
- The VAPID key pair came from the database, generated by the API on first use (ADR-0040 revision). No SSM stand-in was needed.
- Seed data: the `dev:db` fixture, plus one practice created through `POST /api/sessions` two hours before the run, with "Set principal" attached.
- Notification permission was granted with CDP `Browser.grantPermissions`, from a client that stayed connected. Push was delivered for real: the build subscribed to FCM through the sandbox proxy, and `registration.getNotifications()` read what the service worker displayed.
- Members: Hugo drove the browser. Léa and Marc acted through `curl` with their own session cookies, or in a second browser session.

## Notes

- **46 FAIL.** On the 1280 px new-song form the Deezer field sits at the top and Save sits about 1 560 px down, in the normal page flow. After the 409, the refusal appears in an `aria-live` paragraph above the form. The page does not scroll, the focus does not move, and the area around Save does not change. A sighted member sees no reaction to Save; a screen reader announces the message. At 375 px Save is pinned to the bottom of the screen and the page is not scrolled, so the message is in view. The message text and link are correct (row 45). It is the placement that fails at desktop width.
- **28.** Needs iOS Safari.
- **32, 42.** Not set up in this run. The 0102 run proved both with a second subscribed browser and an unreachable endpoint. Nothing in the push path changed since then except moving the VAPID key pair into the database, which rows 20, 33 and 35 exercise.
- **36.** Headless Chromium cannot click a system notification. The payload URLs are right.
- **49.** The same `argent.sh` path bug as in the 0102 run is still there. No CDP touch fallback was run this time, so tap behaviour is unproven by this run.
- **Observation, not a row.** In the first browser session, around its 350th command, a cut recording (row 39's method) left a queue entry with `byteLength: 0` that never uploaded and never showed as failed, while the sheet said the take was saved. The session stopped answering on the next command. A fresh session, with the same steps run twice, produced 140 KB of chunks and created both takes. I could not reproduce it, so it is not counted. If it is real, a zero-byte entry stays in the queue with no failure state.
- **Observation.** At 1280 px with an Android phone user agent the banner still shows. That matches the spec, which keys on the device rather than the width; row 15 used desktop user agents.
- Console: `errors` was read once, on the concert session page, and was empty. It was not read on every screen.

## Verdict: FAIL
