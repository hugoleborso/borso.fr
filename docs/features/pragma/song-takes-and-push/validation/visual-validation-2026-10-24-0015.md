- Spec: [`../spec/spec.md`](../spec/spec.md)
- Dev URL: http://localhost:5174/ (`pnpm --filter @borso-app/pragma dev`), plus a production build on http://localhost:4173/ (`vite preview`) for the push rows, because the service worker only registers outside dev
- Run at: 2026-10-24T00:31:44Z
- Tooling: agent-browser 0.27.0, Chromium 1243 headless, launched with `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream` as the spec's test strategy asks
- Branch: `claude/pragma-takes-and-push` at `d4a31ea9`

## Harness

The local API has no bucket and no SSM parameters, so the run stood up a stand-in for both rather than leave the upload and push rows untested:

- `AWS_ENDPOINT_URL_S3` and `AWS_ENDPOINT_URL_SSM` pointed at a small local HTTP server on port 9000 that stores `PUT` bodies, serves them back with range support and CORS, and answers `GetParameter` with a freshly generated VAPID key pair. `UPLOADS_BUCKET=pragma-local`, dummy AWS keys. Presigned URLs resolved to `pragma-local.localhost:9000`.
- Seed data: one practice session created through `POST /api/sessions` dated two hours before the run, with the seeded "Set principal" setlist attached through `POST /api/setlists/:id/sessions`.
- Notifications permission was granted with CDP `Browser.grantPermissions`, held open by a background client for the push rows.
- This run was executed by the workflow subagent directly: the subagent has no `Agent` tool to dispatch the dedicated `visual-validator`, so the standalone-agent rule could not be applied as written.

## Notes

- **06 (FAIL).** At 375 px each take row truncates its one line with an ellipsis right after the session name, so the duration and the member, two of the four facts the spec's row carries, are hidden on a phone, which is where the band records. Measured on both Slow Burn rows: span 194 px wide holding 255 px of text, `text-overflow: ellipsis`, no `title` fallback. At 1280 px the full line shows (row 05).
- **15, 30–34, 40.** The push service itself is not reached in this sandbox, which the spec's test strategy states and assigns to the back-end e2e with a faked adapter, plus one manual iPhone smoke after deploy. 34: the address a notification would open (`/catalog/<song>?take=<id>`) does open that take.
- **25.** Background sync behaviour on iOS needs iOS Safari; nothing here runs it.
- **28.** The takes are gone after a song delete (row 27). The audio delete was attempted: the API logged `{"event":"TakeObjectDeleteFailed","objectKeys":["take/d3754abe-…/2cae2047-….webm"]}` because the local S3 stand-in does not answer `DeleteObjects` the way S3 does, and the request still returned 200. Comments of a deleted take have no page to look at.
- **37.** The handler was driven by ending the capture track, which is how capture stops when iOS locks; a real lock was not reproduced.
- **44.** `scripts/argent.sh` looks for `chrome-linux/chrome`, and this image ships `/opt/pw-browsers/chromium-1243/chrome-linux64/chrome`, so no real touch could be sent. Every row above was driven by synthetic clicks.
- Console: one React warning about `memberRows-testid` on the Members page, outside this feature. No broken `<img>` on any screenshot.

## Verdict: FAIL
