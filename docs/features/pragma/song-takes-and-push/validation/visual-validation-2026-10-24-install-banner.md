## Notes

- **07 UNVERIFIABLE.** Headless Chromium does not draw its install prompt, so nothing on screen shows "Chrome's own prompt" opening. What the run did prove: Chromium fired a trusted `beforeinstallprompt` on `localhost:5174`, the Install button appeared only then (rows 05 and 06), clicking it called `prompt()` exactly once on that deferred event, and headless Chromium resolved `userChoice` to `dismissed`. The app then closed the sheet and left the banner up, which is the right result for a dismissed prompt. Seeing the system prompt itself needs a real Android phone.
- **How rows 09 and 10 were emulated.** Chromium ignores `display-mode` in CDP `Emulation.setEmulatedMedia` without reporting an error. I tried that first, and `(display-mode: standalone)` stayed false after a reload. agent-browser has no setting for it either. So row 09 replaces `window.matchMedia` with an init script that matches `(display-mode: standalone)` only, and row 10 makes `navigator.standalone` true. Both are the signals the spec names. They exercise how the app reacts to installed mode, not the browser's own media evaluation.
- **Row 14 is outside the brief's list.** The edge case says "phone or tablet", so I added an iPadOS check. iPadOS Safari reports a macOS user agent, and headless Chromium reports `maxTouchPoints = 0`. An init script set it to 5, as on a real iPad.
- **Rows 04, 05 and 13 were captured by intervention.** For the frames in 11, 13 and 16, I paused the loop animation at 200 ms so step 1 could be captured; rows 02 and 03 show the unpaused loop. Row 05 stops the trusted `beforeinstallprompt` in the capture phase to stand in for "Chrome has not offered it". Row 13 makes `setItem` throw from the console after the page loaded.
