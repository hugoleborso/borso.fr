# Visual validation — The band sees the next two-hour slots when every member is free, and books a practice in one tap

- Spec: [`../spec/spec.md`](../spec/spec.md)
- Dev URL: https://pragma-pr-118.preview.borso.fr/ (API https://pragma-pr-118-api.preview.borso.fr)
- Run at: 2026-10-02T14:48:07Z (now = Fri 2 Oct 2026, from 16:48 Europe/Paris); row 23 at 2026-10-02T16:06:26Z (18:06 Paris, inside the Friday window)
- Tooling: agent-browser 0.35.2 (through `scripts/browser.sh`, started with `TZ=Europe/Paris`, one session per member); argent (through `scripts/argent.sh`) for rows 08 and 09

Setup: `POST /api/__test/seed` at the start (200, `"calendarFeeds":3`) and again before the booking, 375 px and phone pass. Each scenario was built by members saving or removing their own feed, through the Account page (rows 01–03, 10) or `PUT`/`DELETE /api/me/calendar-feed` with the member's own session. Expected slots were worked out by hand from the fixture bodies (read with `curl`) before they were compared with `GET /api/free-slots` and the screen. Crafted feeds were served by `https://httpbin.org/base64/<ics>`, status codes by `https://httpbin.org/status/<code>`, redirects by `https://httpbin.org/redirect-to`. The pixel-content scan for broken `<img>` returned `[]` after every agent-browser screenshot; the argent screenshots (21–23) show the same pages, which were scanned in agent-browser.

## Notes

No FAIL or UNVERIFIABLE row. Observations, not verdicts:

- Rows 06 and 09: `session.origin` is not returned by any API response (`GET /api/sessions/:id` lists no `origin`), so the stored value was read from the request body and the API's enum validation, not from the database.
- Row 25: with no feed connected, `GET /api/free-slots` still returns all 28 window slots, with every member `no-calendar`. The screen shows the empty state as the spec asks; only the API body differs from what the block displays.
- Row 28: `slow.ics` answers `404` after about 6.4 s when fetched with `curl`. The API's `unavailable` at 4.46 s shows the 4 s limit fired first; a 404 read in full would have given `needs-reconnecting`.
- Environment: after `POST /api/__test/seed`, a browser session signed in before the seed kept showing the app shell while `/api/me` answered 401; Hugo's Account page then showed the empty Calendar field even though the seed had given him a feed. Clearing cookies and signing in again fixed it. A browser session also signed out on its own during the hour's wait before row 23. Neither is a claim of this spec.

## Verdict: PASS
