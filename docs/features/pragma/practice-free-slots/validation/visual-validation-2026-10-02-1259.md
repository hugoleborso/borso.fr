## Notes

- **12 FAIL (busy time in another time zone is ignored).** The seeded `sarah.ics` has a one-hour event at 12:00 America/New_York on Mon Oct 5, which is 18:00–19:00 in Paris, inside the weekday window. With Sarah's feed included, the Oct 5 slot is still 18:00 – 00:00 (`16:00Z–22:00Z`), so the screen offers a practice while a member is busy. The served feed has no `VTIMEZONE` block (`grep -c VTIMEZONE` = 0), so the event is probably read as floating Paris time (12:00–13:00, outside the window) instead of being resolved through the IANA zone. The fault is either the fixture, which is part of this feature per the Developer perspective, or the adapter's handling of a `TZID` without a `VTIMEZONE`. Either way, the preview shows a wrong slot.
- **28 FAIL (save-time localhost check misses the trailing-dot form).** `https://localhost./cal.ics` and `https://LOCALHOST./cal.ics` are accepted at save time, while `https://localhost/` and `https://LOCALHOST/` are rejected. `localhost.` is the fully-qualified form of the same loopback name. The read-time guard then excludes the member as `unavailable` (row 29), so no loopback content was observed. Still, the save-time rejection the spec requires does not happen for this form. `https://localhost.localdomain/` and `https://127.0.0.1.nip.io/` were also accepted at save time; those are DNS names, which the spec leaves to the read-time check, so they are not counted against this row.
- **17 UNVERIFIABLE.** The fixtures contain no `ATTENDEE;PARTSTAT=DECLINED` event, and the save-time guard allows only https addresses (no data: URI, no local file), so no feed could be written for it.
- **18 UNVERIFIABLE.** No fixture event crosses midnight (`sarah-late` ends at 23:59). The same limit applies as in row 17.
- **22 UNVERIFIABLE.** Any combination of the hugo, marc and sarah fixtures leaves Sun Oct 4 19:15–23:00 free, and gone/slow only exclude members, so the "no slot" message could not be produced.
- **23 UNVERIFIABLE.** The run took place between 15:01 and 15:27 Paris time. Today's window opens at 18:00, so the cut at now could not be observed; the first slot correctly started at 18:00.
- **27 UNVERIFIABLE.** The size limit is not stated in the spec, and an oversized non-ICS body would also fail to parse, so "over the size limit" cannot be told apart from "does not parse" (which passes in row 26).
- Observation on row 05, not a verdict: in the first pass the browser ran in UTC. The block showed "19:15 – 23:00" (Paris time), while the dialog opened at 17:15 (the browser's local time); see `./visual-validation-2026-10-02-1259/03-sessions-utc-browser-1280.png` and `./visual-validation-2026-10-02-1259/04-book-dialog-utc-browser-1280.png`. The instant is the same, but a member whose device is not on Paris time sees two different times for one slot. The spec does not say which time zone the form uses, so this is not counted.
- Observation, not a verdict: with few feeds connected the block lists every free evening (27 rows), which pushes the session list below the first screen (`./visual-validation-2026-10-02-1259/07-marc-sarah-windows-full-1280.png`). The spec sets no cap on the number of rows.
- Environment: one `POST /api/__test/seed` returned `500 Internal Server Error`, after members had removed and re-added feeds and free-slot practices existed. The immediate retry returned 200.

## Verdict: FAIL
