## Notes

- Row 31. `RequireSession` keeps the route under its opening screen until the `/api/me` probe answers, and `pragma.query-cache` in localStorage restores the member on later loads. With `/api/me` delayed by 4 s and the cache cleared, the page still rendered with the opening chart selected. The "first chart while loading, then replaced, unless a pill was tapped" sequence is therefore never visible in a browser. The unit tests for the switcher state are the only place it can be checked.
- Row 32. A tab "opened before the deploy" needs the previous production bundle running against the new API. That cannot be reproduced on `pnpm dev`.
- Row 33. The `get_song` and `save_song` MCP tools and the unknown-name refusal have no page to drive. This is the technical validator's ground.
- Observation outside the assertions. On the song page, Lightning's PDF chart body reads "sign-get 500" (screenshot 18). The cause is the fake `s3Key` and the missing upload bucket on `pnpm dev`, not this feature (inferred: uploads need a preview per CLAUDE.md). The pills and their kind icons render correctly.
- Observation. The spec's example pill "Guitare + Piano" renders here as "Clavier + Guitare", because the seed has no Piano and lists Clavier before Guitare in instrument order. That matches the Q.O.D. rule "instrument names in instrument order".
