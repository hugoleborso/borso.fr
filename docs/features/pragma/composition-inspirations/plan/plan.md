# Plan — Members sketch a composition from passages of songs they love

> Early quality check. Pair with [`../spec/spec.md`](../spec/spec.md) as of commit `e5109b206` (Deezer search revision). When a defect lands and a Dantotsu traces back here, the chain is visible: the plan either named the risk and we missed mitigating it, didn't name the risk at all (planning gap), or named it correctly and the defect comes from elsewhere.

Goal: give the band a shared library of YouTube passages and a per-composition timeline sketch, so more compositions get written. The smallest change is the spec as written, with the corrections below where the spec's Files-to-change list did not match the code.

### API surface and payloads

All routes sit behind `requireMemberSession`. Ids of new rows are generated by the client (`crypto.randomUUID()`), and inserts use `onConflictDoNothing`, as `hasInsertedTakeWithin` does, so a retried POST lands on the same row.

| Route | Body | Answers |
|---|---|---|
| `GET /api/inspirations` | none | `200 { inspirations: InspirationView[] }`, newest first (`created_at desc, id desc`) |
| `POST /api/inspirations` | `{ id, youtubeVideoId, title, artist, deezerTrackId \| null, deezerAlbumId \| null, startSeconds, endSeconds, note }` | `201 { inspiration }`. `400` from `zValidator` when the id pattern or the passage rule fails. |
| `PATCH /api/inspirations/:id` | every field of the create but `id` | `200 { inspiration }`, `400` on the same rules as the create, `404 { error: 'inspiration-not-found' }` when it was deleted meanwhile |
| `DELETE /api/inspirations/:id` | none | `200 { id, deleted: true }`, `404 { error: 'inspiration-not-found' }`, `409 { error: 'inspiration-in-use', sketches: [{ songId, title }] }` |
| `GET /api/sketches/:songId` | none | `200 { sketch: { songId, lanes, clips } }`, `404 song-not-found` |
| `POST /api/sketches/:songId/lanes` | `{ id, name, position }` | `201 { lane }`, `404 song-not-found` |
| `PATCH /api/sketches/:songId/lanes/:laneId` | `{ name }` | `200 { lane }`, `404 lane-not-found` |
| `DELETE /api/sketches/:songId/lanes/:laneId` | none | `200 { id, deleted: true }`, `404 lane-not-found` |
| `POST /api/sketches/:songId/clips` | `{ id, laneId, inspirationId, offsetSeconds }` | `201 { clip }`, `404 lane-not-found` or `inspiration-not-found` |
| `PATCH /api/sketches/:songId/clips/:clipId` | `{ laneId, offsetSeconds }` | `200 { clip }`, `404 clip-not-found` or `lane-not-found` |
| `DELETE /api/sketches/:songId/clips/:clipId` | none | `200 { id, deleted: true }`, `404 clip-not-found` |

`InspirationView` is the `inspiration` row plus `authorName: string | null` (left join on `member`, like `TAKE_PROJECTION`) and `sketchCount: number`. A lane belongs to the path's song: every lane claim is `WHERE id = :laneId AND song_id = :songId`, so a lane of another song reads as `lane-not-found`. A clip write is `WHERE id = :clipId AND lane_id IN (lanes of :songId)`.

### Pattern coherence pass

- **New pattern:** the YouTube IFrame Player API, a script loaded at runtime from `www.youtube.com/iframe_api`. It does not replace `OembedFrame`, which keeps serving song links where nothing needs the current time or an end second. Two players for two needs, written down here so a reviewer does not merge them.
- **CSP:** none to change. The site is served by `infra/cdk/src/constructs/static-site.ts` with `ResponseHeadersPolicy.SECURITY_HEADERS` (no Content-Security-Policy). `grep -rni "content-security-policy\|frame-src\|script-src"` over `apps/pragma` and `infra` finds nothing, and `site/index.html` sets no meta CSP. The service worker does not intercept fetches. `www.youtube.com/iframe_api` answered `200` from this sandbox (measured).
- **dnd-kit:** reused, `@dnd-kit/core` only (`useDraggable`, `useDroppable`). `@dnd-kit/sortable` is not needed because lanes are free, not sorted.
- **Deezer search:** reused from `AddSongForm.tsx` piece by piece. Extracting a shared organism would touch `AddSongForm` and its tests for about thirty lines of markup, so the plan does not extract.

## Open questions / unknowns

All four were decided by the operator after this plan was written, and the rows above carry the decisions.

- **Can an inspiration be edited?** The operator chose every field, the passage included, through `PATCH /api/inspirations/:id`. Placed clips keep their offset and take the new length.
- **The 5xx Sentry tag `feature:composition-inspirations`.** The operator chose no per-feature tag. The route-named transaction is enough.
- **Should the API refuse a sketch on a song that is not a composition?** The operator chose no server check. The site links a sketch from compositions only.
- **Starting zoom.** The operator chose `PIXELS_PER_SECOND = 8`, a guess `/visual-validation` judges.
