## Notes

- **12 (FAIL), missing "In the catalogue" badge.** Reproduced through the UI alone. Hugo had sketch Repro Y open. Marc tapped Add to catalogue on Composition 7. Hugo then tapped Add to catalogue on Repro Y and went back to `/compos`. Composition 7 showed no badge after a 5 s wait and after a full reload, while `GET /api/compositions` returned its `songId` and Marc's list showed the badge (`41-…`, `42-…`). Hugo's persisted `pragma.query-cache` held `["compositions","list"]` with Composition 7 `songId: null`, `isInvalidated: false` and a fresh `dataUpdatedAt`, so the reload did not refetch (measured). The likely cause is that Hugo's own catalogue success wrote into the cached list and cleared the invalidation Marc's write had set (inferred). The badge came back only when a later write by another member invalidated the list again. Live invalidation works when the list is on screen: Marc catalogued Composition 8 while Hugo watched `/compos`, and the badge appeared within 3 s. The same stale state also showed up first on Last Loop Anthem, `40-compos-list-badges-1280.png`.
- **48 (FAIL), "former member" not shown to the member who deleted.** Hugo deleted Sarah on `/members`. The API then returned `authorMemberId: null, authorName: null` for "Sarah pick". Hugo's library still read "Sarah · in 0 sketches" after opening the page, a full reload and in-app navigation (`54-…`). His cached `["inspirations","list"]` had `isInvalidated: false` (measured). Marc, whose cache was older, read "former member" (`55-…`). The member delete does not appear to invalidate the inspirations list for the member who made it (inferred).
- **09, 28, 34 (playback).** The embedded YouTube player showed "Video unavailable" for every id in this headless sandbox, so "Set start here", "Set end here" and pause at the end second could not be observed. The spec's test strategy calls real playback not automatable and asks the validator to assert the `start` and `end` the player gets: `start=52&end=64`, then `start=52&end=70` after the edit, and `start=220&end=232`.
- **53.** The run before this one could not reach the reload path for `inspiration-not-found` and `clip-not-found`. Here, firing the other member's delete in the same beat as the click reached it. Each request answered 404 and the banner appeared on a page reloaded just before. A slower race still loses to live invalidation: a drag held while its clip was deleted sent no request, because the clip vanished mid-drag.
- **Observation (not a spec row), stale error after another member's catalogue.** Hugo's failed Add to catalogue left "The composition was not added to the catalogue. Try again." on screen. When Marc's catalogue landed, Hugo's header switched to "In the catalogue" and "Open the song", but the error stayed under it (`38-stale-error-after-other-catalogue-1280.png`).
- **Observation, row 46 placement.** The error sits on its own line under the header row, left-aligned, not directly under the right-aligned button (`36-catalogue-error-1280.png`).
- **Observation, accessibility.** After a drop, the dnd-kit live region reads "Draggable item 6f954b8f-… was dropped over droppable area 773c9751-…", so a screen reader hears UUIDs. The member delete buttons on `/members` are all named "Delete", without the member's name.
- Rows 37, 45, 51 and the API probes in 52 to 54 used `fetch` from a signed-in page, because agent-browser cannot land two pointer gestures in the same millisecond.

## Verdict: FAIL
