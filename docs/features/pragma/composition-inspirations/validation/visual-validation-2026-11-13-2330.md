## Notes

- **09, 20, 26 (playback).** The embedded YouTube player showed "Video unavailable / This video is not available" for both video ids in this headless sandbox. A bare embed of an unrelated id returned Error 153 here as well, so the cause is likely the sandbox (inferred). "Set start here", "Set end here" and pause at the end second could not be observed. The spec's test strategy marks real playback as not automatable. It asks the validator to assert the `start` and `end` the player receives, which are `start=52&end=64` and `start=220&end=232`. The iOS autoplay row named in the plan needs a real phone.
- **41.** The API codes were confirmed by direct calls: `POST /clips` with an unknown inspiration gives 404 `inspiration-not-found`, and `PATCH /clips/<unknown>` gives 404 `clip-not-found`. The UI "reload the sketch" path for these two codes was never reached. Live invalidation removed the inspiration from Marc's open picker and closed his clip sheet before he could act. In the drag race, the "It was reloaded." banner was already on screen from row 40, so the drop's own effect cannot be told apart. The reload was observed only for `lane-not-found`.
- **Observation, cosmetic.** At 375 px the card range wraps after the arrow ("0:52 →" / "1:04"), see `33-library-375.png`. No spec claim covers line breaks, so no row fails.
- **Observation, outside this spec.** Signing in as "Léa" with the seeded password showed "Unexpected error." twice, from two fresh sessions. Hugo, Marc and Sarah signed in normally. Marc stood in as the second member.
- Rows 28 and the API probes in 38, 39, 41 and 42 used `fetch` from a signed-in page rather than UI gestures. Two pointer drags cannot be made to land at the same moment with agent-browser.
