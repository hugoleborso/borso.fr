## Notes

- **04**: opening the app at `/` returns to Home after sign-in, because `RequireSession` passes `from`. Signing in from `/login` itself, and the password recovery flow, still go to `DEFAULT_POST_LOGIN_PATH`, which is `/catalog`. The spec says the app opens on Home and that browsing songs costs one more tap; this path lands on Songs.
- **09, 10**: tool and seed limits, not observed defects. The audit seed gives no song a duration and the next session is a practice, which cannot carry a venue. Proving both needs a seed with durations and a concert as the next session; writing them through the API on the private instance was refused by the session's permission classifier.
- **27**: the account page is one of slice 2's screens (*Slices* › 2) and gained the Language card in this slice. It keeps five primary pills inline in its cards, four below the fold at 375. The plan's primary count covers `/`, `/band`, `/sessions` and `/setlists` only; the spec's rule covers every screen.
- **28**: the harness counts `button` elements and links separately, so this pill does not appear in its text-only button total; its link row for `/sessions` reports 4 text-only links, the other 3 being the session cards. It is the only visible pill without an icon on the slice 2 screens.
- **29**: the spec says section tabs and chips are choices, not buttons, so the FR and EN chips may be text only by the spec's rules. The acceptance row is defined by the harness count, though, and that count is 2, not 0. Either the chips get an icon, as the catalogue's filter chips have, or the harness excludes `aria-pressed` choices; until then the row reads 2.
- **31**: the router keeps the previous page's scroll offset across a tab change, clamped to the new page's height. Any tab reached from a scrolled screen opens part way down. Task 3b's walk starts from an unscrolled Home, so the harness does not see it.
- **Studies** (not graded): `/studies` shows 23 primary "Studied" pills, one per row. The spec gives Studies to slice 6, which removes the screen, so this row is left to that slice.
- The harness's `meta.standalone` reads `false` in this run although the README says the walks emulate standalone mode; no slice 2 row depends on it.
- Task counts for walks whose path changed by design (1: 18/3/7, 2: 11/2/7, 8: 14/0/8, 8b: 7/0/5, 9: 7/1/4, 10: 7/2/5, 11: 9/9/2) are recorded, not graded: their targets belong to slices 3 to 6.
- Touch rows were driven with `scripts/argent.sh touch` on a Chromium the script started (CDP 9333). argent's tool-server could not start beside the harness's, so text was typed through CDP `Input.insertText` and Escape through `Input.dispatchKeyEvent`; every tap was a real touch.
- Everything started for this round has been stopped: instance 5192, the harness's 5186 instances, argent's Chromium on 9333 and the agent-browser sessions `vv22`, `vv22b` and `vv22c`. The shared local Postgres cluster was already running and still runs.
