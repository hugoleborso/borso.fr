## Notes

- **01, task 9 does not rerun reliably.** In the full run and in two of three runs of `--tasks 9` alone, the walk's first tap on the catalogue's search field leaves focus on `BODY`; the harness records the task as `failed`, and `--compare` then exits 1 on `task 9: failed`. The field was found at y=16 px, which is where it sits before the next-concert strip above it (`NextConcertStrip`) has rendered; the likely cause is that the strip arrives between the find and the tap and pushes the field down by its own height, so the tap lands on the strip. That cause is not confirmed. Task 7 starts with the same tap and passed in the full run. Every count that was produced equals the baseline, so the counts are reproduced; what fails is that a rerun does not finish task 9 three times out of four.
- **10, dark scheme.** The harness's route measures run in the light scheme only (`measureRouteLook` sets no colour scheme), so "both schemes" had no measure. Running its own probe in dark finds one pair: the disabled "Add a passkey" button on `/account`, `rgb(149, 140, 126)` on `rgba(241, 235, 223, 0.12)` over `leaf`, 3.74:1. It passes in light. WCAG does not require contrast on a disabled control. The spec's measure counts it, so either the dark `ink-faint` on `glass` pair is raised, or the spec and the probe say that disabled controls are excluded. [`account-390-dark.png`](./visual-validation-2026-10-27-1609/account-390-dark.png)
- **15, tap targets.** The harness skips every element inside `p` or `li > span` (`COUNT_SMALL_TAP_TARGETS`, `page-probes.setup.ts:232`). The main-instrument toggles on `/instruments` sit in an `li > span`, so the harness never measures them: each is a `min-h-11` button with `px-0.5`, 28 px wide, with a 4 px gap to the next member's toggle. Also seen and not graded: the map's "© OpenStreetMap" attribution link on `/bars` is 278x18 px; it is the map vendor's licence notice, not one of the app's controls.
- **21, `/tasks` at 1280.** At this width the board shows narrow columns, and the task card gives the title what is left between the 44 px checkbox label and the 44 px delete `IconButton`. The title's box overlaps the delete button's box in all 12 cards (for example "Réécrire le pont" at x 347 to 408 against the button at x 392 to 436). The delete control was already 44 px wide on `origin/main` (a `×` button with `min-w-11`); what changed in `TaskRow.tsx` is the title, now `ListRow` with a trailing `chevR` icon and the `text-body` size (16 px, was 13.5 px), in a column too narrow to hold both. At 375 the cards are wide enough and nothing overlaps.
- **13, harness side note.** In the harness's eight note-race runs each run sent one save (`requests: 1`), because typing finishes inside the 600 ms pause; the eight runs pass but never have two saves in flight. The argent run above, with pauses longer than 600 ms and delayed replies, is what exercised the overlap.
- Slice 1 rows not graded here because the spec gives them to later slices: "Not saved" with retry on a failed note save (slice 3 per the plan), the note shown on the row and on the transition line (slice 3), the Lineup grid (slice 3), bottom-third primary actions (after slice 6).
