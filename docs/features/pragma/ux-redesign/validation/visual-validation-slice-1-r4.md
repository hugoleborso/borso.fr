## Notes

- **02, regression from the row 21 fix.** Commit `82dc2b78` passed `isChevronShown={false}` to the task row's `ListRow` in `TaskRow.tsx`, so the wrapper `<button>` that opens a task now holds only the title text and no icon. The harness counts all 12 as text-only buttons; the r3 run counted 0. The commit message names the dropped chevron as a changed property but not this count. The spec sets 0 for slice 1 because `icon` becomes required by type, so this row fails. Either the open button gets an icon back in a layout that keeps the title clear of Delete, or the spec states that a `ListRow` whose whole surface opens an item is not a text-only button, and the harness measures it that way.
- **01** passed in one full run. Round 3 failed three of four runs on task 9, so one clean run is weaker evidence than the four that the fix commit reports. The fix is a reflow at the source (the strip reserves its height) plus a settle check in the walk, which is consistent with the clean run.
- **21, not graded as breakage.** My overlap probe also flags three things that are deliberate: the fixed bottom pills (`New song`, `Add song`, `Save`) pass over rows while the page is mid-scroll, and row 20 shows they clear the content at the end of the page; on `/members` at 375 the mastery matrix scrolls sideways under a sticky AVG column, as its caption "Swipe the grid sideways to reach every instrument" says.
- **Not re-run this round:** the r3 argent checks for rows 13 (three typing bursts with delayed saves) and 14 (Escape on a transition draft). Both rows rest on the harness numbers above, and the harness drives argent itself.
