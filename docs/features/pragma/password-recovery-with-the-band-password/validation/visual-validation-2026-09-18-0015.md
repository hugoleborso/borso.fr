## Notes

- **Row 16 / 29 (passkeys survive a recovery) — UNVERIFIABLE.** `/api/me/passkeys` returns `{"passkeys":[]}` for every seeded member, so there is no registered credential whose survival could be observed, and `agent-browser 0.35.2` exposes no WebAuthn virtual-authenticator command (`open`, `click`, `eval`, `connect` … — nothing that registers an authenticator), so one cannot be created from this harness. The claim is untested in both directions: nothing observed contradicts it, and nothing observed supports it.
- **Row 19 (`app_config` empty → 503) — UNVERIFIABLE.** The application offers no surface that empties `app_config`; producing the state needs a direct write to the dev database, which is outside what this run may change. The sibling claim it leans on — "as login does" — was likewise not exercised.
- **Row 24 (the one-hour window) — UNVERIFIABLE.** The threshold (three failures, fourth refused), the per-address scoping and the clearing-on-success behaviour are all proven (rows 23, 25, 30); only the *duration* of the lockout is not, since it would need the address held idle for an hour. Worth flagging to the operator regardless of the verdict: the rendered copy is the reused `auth.rateLimited` string — *"Too many attempts — try again in a few minutes."* — which the spec explicitly mandates, but it tells a locked-out member "a few minutes" for a window the same spec sets at sixty. That is the spec's own decision, not a defect against it.
- **Not a spec claim, recorded for the operator:** `/enrol` now renders a completely blank page rather than a not-found screen — but so does every unmatched path in this application (`/totally-unknown-route-xyz` is byte-identical), so this is the app's pre-existing no-match behaviour and not something this feature changed. The spec claims only that the enrolment screen goes away, and it has.
- **Checks run on every captured screen.** The broken-image scan (`img.complete && img.naturalWidth === 0`) returned `[]` on all sixteen screenshots; `scripts/browser.sh errors` reported no console errors on `/login`, `/recover` or `/catalog`; `document.documentElement.scrollWidth` is 375 at the 375 px viewport, so no horizontal overflow. A `prefers-color-scheme: dark` pass on `/recover` renders correctly (`./visual-validation-2026-09-18-0015/15-recover-dark-media-1280.png`); the spec makes no dark-scheme or touch claim, so neither produced an assertion row, and no touch-only affordance appears on this screen for `scripts/argent.sh` to exercise.
