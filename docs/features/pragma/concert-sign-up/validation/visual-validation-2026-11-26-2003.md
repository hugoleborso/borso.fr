## Notes

- **Row 42, FAIL.** Removing a registration that the last draw picked leaves it in the winners panel. The list updates at once ("Inscrits (4)" to "Inscrits (3)") and the next draws exclude Camille, measured over eight draws. The "GAGNANTS" panel on screen still names her with her email until the member draws again. A member who removes a fake or duplicate winner therefore still sees it announced as a winner. The spec says the registration "leaves the list and the draw at once", and the confirmation copy says "Cette personne sort du tirage au sort". Reading "the draw" as only the pool for the next draw would make this a PASS, but the shown result is the draw a member reads.
- **Row 44, FAIL.** The removed fan keeps seeing "Inscrit·e". A reload and a new tab of the same browser both showed it, and agent-browser's network log recorded only `GET /api/concert-registrations/upcoming` on load (measured). The persisted query cache in `localStorage['pragma.query-cache']` holds the key `["concert-registrations","remembered","<registration id>"]` with `{"isStanding":true}`, saved right after the sign-up (measured). With that entry removed, the next load sent the check through `POST /api/read-batch`, forgot the registration and showed "Je serai là !" (row 45). The code sets that query's `staleTime` to `CHECKED_ONCE_PER_VISIT = Infinity` in `apps/pragma/site/src/lib/queries/concert-registrations.queries.ts`, and the persister keeps queries for seven days with `buster: __BUILD_VERSION__` (read, not probed further). So the inferred cause is that the "once per visit" check result is persisted across visits, and a removed fan sees "Inscrit·e" until the cache expires or a new build ships.
- **Row 34, UNVERIFIABLE.** No poster can be stored from this sandbox. The local API presigns with a read-only key. The browser's S3 PUT failed with `TypeError: Failed to fetch`, and a bare `curl` PUT to the bucket answered 403. Replacing a poster and seeing the new PNG on `/` needs a PR preview. Everything before the PUT works: the PDF is accepted, drawn and trimmed (row 35), and `poster-upload` answers 200.
- **Observation, no row.** `PATCH /api/concert-registrations/registrations/<id>` with the valid token and an empty JSON body `{}` answered 500 Internal Server Error. The same call with a body answered 200. The UI never sends `{}` ("Passer" sends nothing), so no row fails, but a public endpoint answers 500 to a valid request shape.
- **Observation, no row.** The ERP list shows Jo's email as `jo@orange.fr`, while the sheet received `JO@orange.fr`. Camille's `+concert` tag is kept. The stored email looks lower-cased, which the spec does not ask for or forbid.
- **Observation, no row.** At 320 × 568 the home page's `scrollWidth` is 334, so it scrolls sideways. The rule only asks for 375 px.
- **Rows 16 and 17** wrapped `window.fetch` in the page to delay only the registration POST. Without the delay the opening screen lasts too short to shoot locally.
- **Row 35's evidence** is the PNG the page sent to S3, captured from the PUT and downscaled to 388 × 518, not a screenshot.
- **Dev database state.** `POST /api/__test/seed` was run at the end. It left 0 rows in `concert_registration` and 0 songs titled "Valerie…" (measured with `psql`). The two test concerts, Hier Bar and Le Trabendo, had already been deleted. That seed left Le Petit Bain with no poster, prize or message, so they were written back to the local dev database (`poster_s3_key = 'screenshots/pr-410/video-assets/poster.png'`, the message, "3 bières à gagner", `beer`). The concert's date is now 3 Dec 2026 20:15:46 UTC, from the new seed.

## Verdict: FAIL
