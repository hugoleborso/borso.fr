## Notes

- **Row 12 (FAIL).** The server ranks correctly — after the status change, `GET /api/improvements` returns *Dark mode for the scene view* (`shipped`, 2 votes) in last position, below every `idea` and the `planned` row. The screen does not: after saving the edit the row keeps its position at the top of the list, with the `shipped` badge and the `shipped 1` filter count both updated in place. Only a reload moves it down. So the user-visible claim *"it drops below every open improvement"* does not hold at the moment the member makes the change, which is the moment the assertion is about. The same shape appears on creation: a newly filed improvement is inserted at the top of the list rather than at its ranked position, and settles only on the next full load (`05-created-title-only.png` vs `06-ranked-after-reload.png`) — that one does not break an assertion, since assertion 1 only claims the improvement "appears in the list", but it has the same cause: the mutation writes the row into the cached list without re-applying the ranking.
- Assertions 8–11 are API-only in the spec's own wording (status codes, cookie-less requests); they were driven with `curl` against the preview API host rather than the browser, and are marked as such in the Action column.
- No assertion in this spec depends on touch, so `scripts/argent.sh` was not used.

## Verdict: FAIL
