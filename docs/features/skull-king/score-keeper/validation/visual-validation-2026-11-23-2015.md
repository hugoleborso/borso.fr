## Notes

- **12 FAIL.** A part the current version does not offer makes every stored regular disappear, not only the bad one. One regular with `hair: "pompadour"` emptied the home screen's regulars strip (shot 23). Storage still held 8 entries (`JSON.parse(localStorage['skull-king.regulars']).length === 8`). Observed cause: `readRegulars` in `apps/skull-king/site/src/lib/roster.core.ts` runs `z.array(rosterPlayerSchema).safeParse` over the whole list and returns `[]` on any failure. The `avatar ?? suggestAvatar(index)` fallback is only reached when `avatar` is missing (row 11), never when one part is unknown. The broken-image scan found nothing.
- **17 FAIL.** Typing a regular's name does not keep their pirate. The home screen treats "Gus" as the regular, because his chip leaves the strip. It still seats him with the last pirate and the first free colour (gold), not his stored sand pirate. Observed cause: the name form in `HomeScreen.tsx` always uses `selectNewSeatAvatar(lastPirate, seated)` and `selectFreeMark(seated)` and never looks up the regular with that name. Gus's stored record was unchanged right after (`skull-king.regulars` still had his mullet pirate). Whether the end of the game then overwrites it was not tested. The broken-image scan found nothing.
- Observation on row 18, which still passes. The create-account preview showed the last pirate (shot 26) while the name field read "Hal". The pirate changed to Hal's only once the account existed. So the preview misstates the pirate the account will get.
- The `<img>` scan returned `[]` after every screenshot. The faces are SVG `<image>` data URIs, which that scan cannot see. Decoding each `href` gave naturalWidth 150 for all, so no face was broken.

## Verdict: FAIL
