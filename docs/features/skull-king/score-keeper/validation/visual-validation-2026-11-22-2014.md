## Notes

- 06: tapping the check toggle to "Missed" writes nothing. The API entry keeps `tricks: null`, and a second phone keeps showing "Made" with a balanced tally and an enabled close button. A write happens only when a trick chip is tapped (then the API showed `tricks: 1` and the other phone followed, `./visual-validation-2026-11-22-2014/56-phone-tap-tricks.png`). So "missed, tricks not yet chosen" is a local draft, and another phone can close the round meanwhile. The data shape (`tricks: null` means made) cannot store that state. Either the spec accepts it or the shape needs a missed flag. That is an operator call.
- 08: bid chips use `grid-template-columns: repeat(N, minmax(0, 3rem))`. They are 42 px wide at 375 px with 6 chips and 26 px wide with 9 chips (8 players, round 9). The Harry and Rascal cards are 40 px wide on the results screen and in the correction sheet. Height is fine (48 to 56 px). Every other control on home, invite, scores and the sheet is at least 44 x 44.
- 17: the spec says "four letter code" and `joinCode: string; // four letters`. Codes 8E4G, G75Y and 62CL hold digits. Either the alphabet or the spec wording is wrong.
- 26: the results screen (phase `scoring`) has no Scores button. Bids has one ("Scores") and scores is its own screen. The only way out of results is the pencil back to bids.
- 35: the spec asks for "a gold skull on the night ground". All the icons checked (maskable 512, apple touch 180) show a gold coin with an "SK" monogram on a dark navy ground.
- 36: the dev server skips registration (`if (import.meta.env.DEV) return;` in `site/src/sw/service-worker.setup.ts`), so caching can only be checked on a preview or a production build.
- 40: a signed-in player cannot create a game. The client sends the account's seat as `{"id":"927ab190-…","name":"Vera","icon":"crown","color":"rose"}`. `POST /api/games` answers 400 `{"error":"value-out-of-range"}`. The same body without `id` creates a game (62CL). The home banner shows the bids error text "That number is not possible this round." This breaks "an account never gates a write" and "already linked to the account".
- 42: opening a finished game that has a rematch redirects to the rematch's invite (`/?game=SGRN` → `/?game=VZJR&view=invite`, measured twice). The "Mes parties" tile that shows the winner therefore opens a different game, and the finished game's winner screen cannot be reached again once a rematch exists. The redirect also added VZJR to "Mes parties" although the account never opened that code itself.
- 50, observation: the Rules section defines Rascal's bet as won or lost with the bid, and the app adds it (Anne +10 → +20 → +30). *Out of scope* also lists "Rascal's scoring". The spec contradicts itself. The row follows the Rules section.
- 45, observation: on a guest home the Play button and the 375 px layout leave a large empty band between the marks and the footer. This is not a spec claim.

## Verdict: FAIL
